Travelling CErXes engine

A CErXes engine's whole state (objects, compiled code, a suspended script's frames) can be written out as text and a new engine made from that text, here or somewhere else. Each host below is a Web Worker with its own CErXes WebAssembly instance; the page carries the text between them as a network would, and estimates what a real network would add from the gzip size of every transfer.

The Zoo ranking has the run-time cost: CErXes · detachable runs in 4 ms slices (it can be stopped and moved at any branch, call or return) and CErXes · moving also moves itself every 100 ms.

1. Snapshot speed

Take: the engine as text. Restore: a new engine from the text. Median of 5, one host. gzip: this browser's CompressionStream.

2. One query over every shard, three ways

Each host holds one shard of generated sales rows. The query: count, sum and max per group of the rows from 2023 on.

  • A: the whole engine travels host to host, reads each shard and leaves as a snapshot.
  • B: only its data root (__carry, JSON) travels; every host was given the code once, as a code-only template snapshot, and makes a fresh engine from it.
  • C: map-reduce. The query code goes to every shard at once; the partial results come back and are merged.
